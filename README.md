# Pythia Chat

Экран чата на Expo SDK 57, React Native 0.86, TypeScript strict, Redux Toolkit и RTK Query. Работает в Expo Go, development build не требуется.

## Запуск

Понадобятся Bun, актуальный Expo Go и отдельно предоставленный мок-сервер. Сервер, текст задания и исходный файл Figma в репозиторий не включены.

1. В отдельной папке распакуйте мок-сервер и запустите его через `bun run start` (либо `node server.mjs`, Node.js 18+). Установка зависимостей серверу не нужна. Документация API: `http://localhost:4000/docs`. `bun run start:calm` отключает случайные ошибки для проверки вёрстки.
2. В папке приложения выполните `bun install --frozen-lockfile`.
3. Скопируйте `.env.example` в `.env`. Укажите `EXPO_PUBLIC_API_URL=http://<LAN-IP-компьютера>:4000`.
4. Запустите `bun run start` и откройте QR-код в Expo Go.

Expo Go 57.0.9 из App Store на физическом iPhone требует входа в Expo Go и Expo CLI. Для CLI используйте `bun expo login --browser` и тот же аккаунт, что на телефоне. Если аккаунт создан через GitHub, для формы входа Expo Go можно создать пароль существующему аккаунту в [настройках Expo](https://expo.dev/settings). На проверенном Android и в iOS Simulator приложение запускается без этого шага.

Телефон и компьютер должны находиться в одной сети. `localhost` на физическом телефоне указывает на сам телефон. Для Android Emulator обычно подходит `http://10.0.2.2:4000`, для iOS Simulator на том же Mac — `http://localhost:4000`. При недоступности сервера проверьте firewall, VPN и изоляцию клиентов Wi-Fi. Expo tunnel не делает локальный API доступным автоматически.

После изменения `.env` перезапустите Metro. После сброса мок-сервера перезагрузите приложение: сервер хранит историю только в памяти.

## Что реализовано

- Загрузка и отображение истории, включая `signs` первого сообщения.
- Локальное сообщение появляется сразу. На каждую новую отправку создаётся один UUID `client_message_id`.
- После принятия сообщения отображается `Pythia is thinking...`. Каждый запрос статуса запускается не раньше `Retry-After` предыдущего ответа.
- Ошибка POST оставляет сообщение с `Not sent` и кнопкой `Retry`. Повтор использует исходные ID и текст. Автоматических повторов POST нет.
- Сохранённое сервером сообщение объединяется с локальным по `client_message_id`. Синхронная проверка состояния защищает от двойного нажатия.
- Ошибки GET статуса не меняют отправленное сообщение на ошибочное. Опрос продолжается после новой задержки.
- При уходе в фон таймеры и активный запрос статуса отменяются; после возврата опрос продолжается с сохранённым сроком следующего запроса.
- FlashList v2 переиспользует строки и сохраняет позицию при обновлениях. Автопрокрутка происходит только рядом с концом переписки. Текст черновика хранится в компоненте ввода, поэтому каждое нажатие клавиши не обновляет список.
- Keyboard Controller и safe-area-context учитывают клавиатуру и системные панели. Edge-to-edge включён параметрами уже установленного `KeyboardProvider`; отдельный `react-native-edge-to-edge` требует нативной сборки и не добавлен.
- На поддерживаемой iOS используется нативный Liquid Glass из `expo-glass-effect` для шапки и поля ввода. Проверяются доступность API и настройка понижения прозрачности. На остальных устройствах остаётся обычная поверхность; смена оформления не пересоздаёт поле ввода.
- Собственная вёрстка без UI-кита. Playfair Display и IBM Plex Mono загружаются из локальных ресурсов пакетов, SF Mono не используется. Стрелка назад и кнопка с квадратами декоративные.

## Архитектура и решения

```text
src/app/          сборка зависимостей, провайдеры, жизненный цикл приложения
src/chat/api/     RTK Query, проверка ответов, Retry-After
src/chat/model/   состояния, отправка, опрос, селекторы, тесты
src/chat/ui/      экран, список, сообщения, поле ввода, оформление
```

Для одного экрана выбран модуль `chat` с разделением по ответственности. Дополнительные слои FSD, repository-интерфейсы и второй state manager здесь не решают отдельной задачи. UI получает данные и команды через `useChat`; URL, HTTP и таймеры остаются вне экрана.

**Источник данных.** Подтверждённые сообщения хранятся в нормализованном кэше истории RTK Query. В `outbox` находятся только неподтверждённые отправки. После подтверждения локальная запись удаляется. Состояние сообщения задаётся discriminated union: `sending`, `failed`, `generating` или `done`, без комбинаций независимых флагов. Ключ строки пользователя одинаков до и после ответа сервера.

**Опрос.** Обычный фиксированный `pollingInterval` не подходит: сервер может менять `Retry-After` после каждого ответа. Контроллер последовательно планирует запросы по абсолютному сроку. Поддерживаются секунды и HTTP-date. При отсутствующем/некорректном заголовке используется задержка 3 секунды; сетевой timeout — 15 секунд. Таймер и UUID передаются как зависимости, поэтому реальные HTTP-сценарии можно проверять без ожидания настоящих секунд.

**Граница сети.** Zod проверяет полученный JSON до попадания в модель. Ошибка в структуре ответа не превращается в успешную отправку. Старый ответ истории не перезаписывает уже готовый ответ Pythia состоянием `generating`.

**Один незавершённый ход.** Новая отправка блокируется до завершения ответа, а также пока предыдущее сообщение имеет `Not sent`. В последнем случае доступен явный повтор. Это сохраняет порядок диалога; очередь нескольких независимых отправок не добавлялась.

**Зависимости.** Версии нативных библиотек подобраны через `expo install` под Expo Go. Нативные проекты `ios/` и `android/` не создаются. Docker для приложения не требуется: Metro и отдельно выданный сервер запускаются непосредственно на компьютере.

## Что осталось и ограничения

- Точная графика Figma: звёздный фон, большая сфера и маленькая сфера пока воспроизведены в SVG. Это приближение, а не экспорт оригинальных ресурсов. Требуется финальная сверка размеров/отступов и оригинальных изображений.
- Расширенная проверка на физическом iPhone: ошибки и повтор, длинная история и изменение размеров шрифта. Ошибка с повтором уже проверена в iOS Simulator.
- Профилирование действительно большой истории на устройствах. API отдаёт всю историю за один запрос и не поддерживает пагинацию: виртуализация ограничивает количество смонтированных строк, но не объём ответа и кэша.
- Outbox и черновик не сохраняются после полного завершения приложения. Подтверждённые сообщения и незавершённые ответы восстанавливаются из истории сервера. Для гарантированного повтора неподтверждённого POST после перезапуска понадобилось бы постоянное хранилище ID и текста.
- Нет очереди отправок, офлайн-кэша, навигации и настоящего бэкенда.
